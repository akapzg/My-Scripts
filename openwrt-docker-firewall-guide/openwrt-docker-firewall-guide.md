# OpenWrt Docker 防火墙绕过及旧版规则警告 — 修复教程

## 适用环境

- OpenWrt 23.x / 24.x / 25.x（fw4 防火墙）
- Docker 已安装（dockerd + luci-app-dockerd）
- 有或计划部署 bridge 网络模式的容器

## 问题表现

1. **Docker bridge 容器绕过防火墙**：即使 fw4 未放行端口，外部仍能直接访问容器映射的端口
2. **LuCI 状态页警告**："检测到旧版规则，系统上存在旧版 iptables 规则"

## 根因

### 问题 1：Docker 与 fw4 双层防火墙冲突

OpenWrt 使用 fw4（基于 nftables）管理防火墙，但 Docker 默认会通过 iptables 创建自己的 NAT 和过滤规则：

```
iptables (Docker 管理)   →  优先级更高，先处理容器流量
nftables (fw4 管理)      →  后匹配，Docker 规则绕过后才到它
```

后果：
- Docker 容器端口映射（`-p 8080:80`）自动创建 DNAT 规则，外部可直接访问，fw4 的 input REJECT 策略被绕过
- 容器出站流量由 Docker 的 MASQUERADE 处理，fw4 的转发规则被跳过

### 问题 2：旧版规则警告

Docker 使用 iptables-nft 兼容层创建规则，导致 nftables 中同时存在 fw4 的原生规则和 iptables-nft 管理的表。LuCI 检测到 `iptables-save` 输出非空即弹警告。

## 修复目标

- Docker 不再触碰防火墙，端口映射由 docker-proxy（用户态代理）接管
- fw4 统一管理所有 NAT 和过滤规则
- 清除 iptables-nft 残留表，消除 LuCI 警告

## 修复步骤

### 步骤 1：禁止 Docker 操作 iptables

**方法 A — LuCI Web 界面：**
Docker → 概览 → 配置（右上角）→ 将 "iptables" 开关关闭 → 保存并重启 Docker

**方法 B — SSH 命令：**

```bash
uci set dockerd.globals.iptables='0'
uci commit dockerd
```

效果：Docker 不再生成 iptables 规则。已有的端口映射改由 docker-proxy（用户态进程）接管。

### 步骤 2：daemon.json 兜底配置

UCI 配置在某些情况下（重置、升级）可能丢失，daemon.json 作为备用保障：

```bash
cat > /etc/docker/daemon.json << 'EOF'
{
  "iptables": false,
  "ip6tables": false
}
EOF
```

> 如果已有 daemon.json，用 `jq` 或手动编辑合并以上字段，不要覆盖其他已有配置。

### 步骤 3：fw4 接管容器出站 NAT

在防火墙中添加 NAT 规则，让 fw4 为容器做 MASQUERADE（源地址伪装），覆盖出站到 WAN 和 LAN 两个方向。

**LuCI 操作：**
网络 → 防火墙 → NAT 规则 → 新增：

| 字段 | 值 |
|------|-----|
| 名称 | DockerNAT |
| 协议 | 全部 |
| 源区域 | lan |
| 源 IP 地址 | 172.16.0.0/12 |
| 动作 | MASQUERADE |

> 说明：`源区域 = lan` 在语义上有偏差（应为 docker），但因 NAT 链按出口接口触发，实际行为正确。`源 IP 地址` 精确匹配 Docker 默认网段（172.17.0.0/16 包含在 /12 内），避免误匹配 LAN 设备。

**SSH 等效命令：**

```bash
uci add firewall nat
uci set firewall.@nat[-1].name='DockerNAT'
uci set firewall.@nat[-1].family='ipv4'
uci set firewall.@nat[-1].proto='all'
uci set firewall.@nat[-1].src='lan'
uci set firewall.@nat[-1].src_ip='172.16.0.0/12'
uci set firewall.@nat[-1].target='MASQUERADE'
uci commit firewall
```

效果：一条规则覆盖所有 bridge 容器出站（WAN 和 LAN），源 IP 伪装为路由器地址。

### 步骤 4：禁用 bridge 流量进入 iptables

某些 OpenWrt 固件（如 iStoreOS、FriendlyWrt）存在冲突的 sysctl 配置，导致桥接流量进入 iptables。原生 OpenWrt 通常无此问题，`rm -f` 在文件不存在时不会报错，可安全执行。

```bash
# 删除可能存在的冲突配置
rm -f /etc/sysctl.d/12-br-netfilter-ip.conf

# 立即生效
echo 0 > /proc/sys/net/bridge/bridge-nf-call-iptables
echo 0 > /proc/sys/net/bridge/bridge-nf-call-ip6tables
```

### 步骤 5：清理 iptables 残留规则

重启 Docker 后，旧规则可能仍残留在 nftables 中：

```bash
# 删除 Docker 创建的残余 nftables 表
nft delete table ip filter 2>/dev/null
nft delete table ip nat 2>/dev/null

# 重启防火墙
/etc/init.d/firewall restart
```

### 步骤 6：重启 Docker 使全部配置生效

```bash
/etc/init.d/dockerd restart
```

## 验证

```bash
# 1. iptables 规则应为空
iptables-save
# 期望：无输出（或仅 "# Generated by iptables-save" 注释行）

# 2. Docker 不再有 nftables 表
nft list tables | grep -E 'ip (filter|nat)'
# 期望：无输出

# 3. fw4 DockerNAT 已生效
nft list chain inet fw4 srcnat_lan | grep masquerade
# 期望：有 MASQUERADE 规则

# 4. 容器出站正常
docker exec <容器名> wget -qO- http://httpbin.org/ip
# 期望：返回公网 IP

# 5. LuCI 防火墙状态页不再显示"旧版规则"警告
```

## 修复后架构

```
容器出站(WAN): 容器 → docker0 → fw4 forward → srcnat MASQUERADE → eth0 → 互联网
容器出站(LAN): 容器 → docker0 → fw4 forward → srcnat MASQUERADE → br-lan → 局域网
容器入站(外部): 外部 → fw4 放行规则 → docker-proxy → 容器
                仅在 fw4 显式放行时可达（Docker 无法绕过）
```

## 日常运维

- **新增 bridge 容器**：自动生效，docker-proxy 接管端口映射，DockerNAT 覆盖出站
- **开放容器端口至公网**：在 LuCI 防火墙中添加 Allow 规则或端口转发即可
- **容器无法访问局域网**：检查 DockerNAT 是否存在；部分 Linux 主机（如 Ubuntu 的 ufw）可能拒绝非本地子网的源 IP
- **回退**：`uci set dockerd.globals.iptables='1' && uci commit dockerd && /etc/init.d/dockerd restart`
